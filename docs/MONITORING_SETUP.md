# 全トークの未対応候補を確認する（20261005版）

1. LINE WORKS Developer Consoleの今回のAPIアプリに `monitoring.read` を追加して保存します。既存のBot権限を残します。
2. AI用の画面だけ停止し、この版の `start-pc.cmd` を起動します。トンネルは起動したままにします。
3. http://127.0.0.1:8787 の「全トーク分析（20261005版）」で有効化し、本人登録済みの閲覧者を選んで保存します。ユーザーが複数の場合は本人登録時のIDと照合してください。
4. 「全トーク取得をテスト」を押します。成功時の行数を確認します。このボタンはAI分析を行いません。
5. 選んだ閲覧者のBotとの1対1トークで `/review-week` または「先週の未対応を教えて」と送ります。

先週は日本時間の月曜〜日曜。先週の依頼について、その後の返信も実行時点まで取得して確認します。10月5日に実行した場合、対象依頼は9月28日〜10月4日です。

## 対象と制約

Monitoring APIが返した範囲を分析します。Botが参加していない通常のトークも取得対象になり得ますが、会社のモニタリング・保存期間・契約・API権限によって範囲が変わります。「全件の網羅」は実データで確認する必要があります。0行を未対応なしとは扱いません。

CSV本文をログや別の保存ファイルには残しません。分析には選択したChatGPTモデルの利用枠を使用します。結果は指定閲覧者の1対1トークだけに返信します。長い結果は番号を付けて複数メッセージに分けて返信します。他の登録ユーザーやグループには全トーク分析結果を返しません。通常の質問にはこの履歴は渡しません。

修正版5から、完了した分割の分析メモをPCの保護された保存先に保存します。同じモデル・閲覧者・対象週で再実行すると、前回の取得時点までの履歴を取得し直し、内容が同じ場合だけ完了分から再開します。成功または接続解除でメモを削除します。以前の版で失敗した処理のメモは復元できません。エラーには停止した段階を表示します。

CSVは最大8 MiB、分析用データは最大150分割（各約60000文字）。全分割を分析後、長いメモを段階的に統合します。AI処理回数は分割と統合の件数によって変動です。途中エラーや上限超過なら、完全な分析結果として返しません。ChatGPT利用枠を消費し、有料APIへの切替はありません。件数により数分以上かかることがあります。「接続状況」の処理欄で進行を確認できます。

未対応は候補です。電話、口頭、別のサービスで完了したことは判別できません。分割された会話で判定を誤ることもあります。トーク・日時・行番号の根拠を元に担当者が確認してください。添付ファイル本文の解析には対応していません。

403時はmonitoring.readと管理者画面のモニタリング設定を確認します。CSV形式エラーや未対応のダウンロード先では、内容や認証情報をチャットに貼らず、PC画面のエラー文のみで確認します。
